# Голосование и опросы

## Назначение

Веб-приложение для создания голосований и сбора ответов. Автор создаёт голосование
с заголовком, описанием и вариантами ответа, получает ссылку на него и отправляет её
участникам. Участник переходит по ссылке, выбирает один вариант и отправляет голос.
Автор видит результаты в своём профиле.

Голосования не публикуются в общем списке: пройти голосование можно только по ссылке.

## Роли

- **Гость** - может пройти голосование по ссылке. Профиль ему недоступен: вместо него
  показывается сообщение о том, что нужно зайти в аккаунт.
- **Авторизованный пользователь** - дополнительно может создавать свои голосования,
  смотреть их результаты и удалять их.

## Основные пользовательские сценарии

1. **Регистрация и вход.** Пользователь нажимает "Войти" в шапке, в модальном окне
   вводит логин и пароль либо переключается на регистрацию. После входа модальное окно
   закрывается, а в шапке вместо кнопки "Войти" появляется его логин и кнопка
   "Открыть профиль".
2. **Создание голосования.** Пользователь открывает профиль, нажимает
   "Создать голосование", заполняет заголовок, описание и варианты ответа
   (варианты можно добавлять и удалять), сохраняет голосование.
3. **Отправка ссылки участникам.** Пользователь открывает своё голосование из профиля
   и передаёт ссылку на него тем, кто должен проголосовать.
4. **Прохождение голосования.** Участник переходит по ссылке, выбирает один вариант
   ответа и нажимает "Подтвердить". Если он уже голосовал, вместо вариантов ответа
   показывается сообщение "Ваш голос отправлен".
5. **Просмотр результатов.** Автор в профиле видит по каждому голосованию все варианты
   ответа со шкалой заполнения, процентом голосов и точным числом голосов в скобках,
   а также общее число голосов.
6. **Удаление голосования.** Автор удаляет ненужное голосование из профиля.
7. **Выход из аккаунта.** Пользователь нажимает "Выйти" в профиле, после чего попадает
   на главную страницу и снова становится гостем.

## Экраны

| Экран | Маршрут | Содержимое |
| --- | --- | --- |
| Главная | `/` | Описание сервиса: создать голосование можно через профиль, пройти - только по ссылке |
| Голосование | `/vote/:id` | Заголовок, описание и варианты ответа с кнопкой "Подтвердить"; после голосования - сообщение об отправке голоса |
| Профиль | `/profile` | Логин, кнопка выхода, список своих голосований с результатами и кнопками "Открыть" и удаления; неавторизованному пользователю - сообщение о том, что нужно зайти в аккаунт |
| Создание голосования | `/create` | Форма с заголовком, описанием и редактируемым списком вариантов ответа |

Поверх любого экрана могут открываться модальные окна входа и регистрации.

## Модель данных

Данные хранятся в PostgreSQL, таблицы описаны SQLAlchemy-моделями в
`src/backend/db/Models.py`.

| Таблица | Поля | Назначение |
| --- | --- | --- |
| `users` | `id`, `username`, `password` | Пользователи. Логин уникален, пароль хранится в виде bcrypt-хеша |
| `polls` | `id`, `author_id`, `title`, `description` | Голосования. `author_id` - ссылка на автора из `users` |
| `vote_options` | `id`, `poll_id`, `option_text`, `votes_count` | Варианты ответа. Число голосов хранится прямо в варианте счётчиком |
| `user_polls` | `id`, `user_id`, `poll_id` | Отметка о том, что пользователь уже голосовал в этом голосовании |

Связи между таблицами:

- у пользователя может быть много голосований (`users` - `polls`, один ко многим);
- у голосования может быть много вариантов ответа (`polls` - `vote_options`,
  один ко многим, варианты удаляются вместе с голосованием);
- участие в голосованиях - таблица `user_polls` между `users` и `polls`.
  Перед тем как засчитать голос, backend проверяет, нет ли в ней уже такой пары,
  поэтому проголосовать дважды нельзя.

Правила, которые проверяются на уровне моделей:

- логин - минимум 3 символа и без пробелов;
- пароль - минимум 8 символов, перед сохранением хешируется bcrypt;
- заголовок голосования не может быть пустым;
- вариантов ответа должно быть больше одного, пустой текст варианта запрещён.

## Настройка и запуск

Нужны установленные Node.js и Python 3.11+, а также запущенный сервер PostgreSQL.

### Backend

1. Создать виртуальное окружение и установить зависимости:

```bash
cd src/backend
python -m venv .venv
.venv\Scripts\activate
pip install fastapi uvicorn sqlalchemy psycopg2-binary python-dotenv bcrypt
```

На macOS и Linux окружение включается командой `source .venv/bin/activate`.

2. Создать файл `src/backend/.env` с параметрами подключения к PostgreSQL
   (файл добавлен в `.gitignore`, в репозиторий не попадает):

```
DB_USER=postgres
DB_PASSWORD=пароль_от_postgres
DB_HOST=localhost
DB_PORT=5432
DB_NAME=vote
```

Указанного пользователя должно хватать прав на создание базы данных. Имя базы
подставляется в запрос как есть, поэтому в `DB_NAME` лучше писать простое имя
латиницей без дефисов и пробелов.

3. Запустить сервер:

```bash
cd src/backend
uvicorn main:app --reload
```

API поднимется на http://127.0.0.1:8000, автоматическая документация - на
http://127.0.0.1:8000/docs.

### Подготовка базы данных и создание таблиц

Отдельных команд и миграций нет, всё делается при старте backend:

1. приложение подключается к служебной базе `postgres` и выполняет
   `CREATE DATABASE`, если базы из `DB_NAME` ещё нет (если есть - шаг пропускается);
2. подключается уже к своей базе;
3. вызывает `Base.metadata.create_all`, который создаёт недостающие таблицы
   `users`, `polls`, `vote_options` и `user_polls`.

То есть достаточно установленного PostgreSQL и заполненного `.env` - остальное
приложение сделает само. Но менять существующие таблицы `create_all` не умеет:
если поля в моделях изменились, старые таблицы нужно удалить вручную, чтобы они
создались заново.

### Frontend

```bash
cd src/frontend
npm install
npm start
```

## Текущее состояние

Frontend и backend пока не связаны между собой.

На стороне frontend (React и React Router) данные голосований заданы в коде как
тестовые. Авторизованный пользователь хранится в состоянии приложения, пароль не
проверяется, а при перезагрузке страницы вход сбрасывается.

На стороне backend (FastAPI и SQLAlchemy) готовы модели и вся работа с базой: создание
пользователя, создание и удаление голосования, голос за вариант, защита от повторного
голосования и выборка голосований автора. Наружу через API выведена пока только часть
этих операций - работа с пользователями и получение голосования по id.
